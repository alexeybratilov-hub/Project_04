## 2. Фактическое состояние проекта

**Продукт.** «ОТ-База» — автоматизация документооборота специалиста по охране труда: событие жизненного цикла → пакет обязательств (документы + сроки) → контроль исполнения.

- **Модули (этапы).** 7 модулей = 7 вкладок: штатное расписание, сотрудники (базовые), инструктажи, медосмотры, СИЗ, СОУТ, несчастные случаи. Установка/снятие — «Вкладки → Модули этапов»; отключение скрывает вкладку, данные сохраняются. Новая база стартует с двух базовых модулей.
- **События и нормы 29н/766н.** Приём (8 требований), перевод (3), увольнение (3), несчастный случай (3). Идемпотентно по событию; уволенные исключаются из расчёта пакетов. Справочник `occupationNorms.ts` связывает должности с вредными факторами 29н и нормами СИЗ 766н с автопересчётом в карточке работника.
- **Матрица требований.** Учитывает должность и класс условий труда (медосмотр 2.0 — 24 мес., 3.x — 12 мес.; обучение руководителей — 36 мес.), у каждого требования указана нормативная база.
- **Документы и пакетная выгрузка.** 10 встроенных шаблонов (8 индивидуальных + 2 групповых с `[ТАБЛИЦА]` для протоколов и листов ознакомления) + собственные `.docx`; пакетная генерация из карточки работника; выгрузка в единый `.zip`-архив; реестр и архив версий; при подключённой папке — запись в `documents/<Категория>/`.
- **Импорт 1С:ЗУП, ГИТ и календарь РФ.** Пресет импорта 1С:ЗУП с автосозданием недостающих должностей; отчёт **«Готовность к проверке ГИТ»** по 9 категориям с экспортом DOCX/PDF/XLSX; предзагрузка праздников РФ на 2026 и 2027 гг.
- **Хранение и безопасность (152-ФЗ / B2B).** (1) рабочая папка через File System Access API (`data/ot_database.json` + бэкапы), (2) `localStorage`, (3) `OT-Baza.exe` с локальным сервером. Уязвимый `xlsx` полностью заменён на `ooxmlWorkbookService.ts` (`fflate`); добавлены обезличивание ПДн для облачных LLM, шифрованные бэкапы (`PBKDF2-SHA256` + `AES-256-GCM`), защита JSON от prototype pollution, поуровневый журнал аудита (`AuditLogModal`) и документация по подписи Windows EXE (`signtool.exe`).
- **Интерфейс.** Liquid Glass + Bento: градиентный canvas, стеклянная оболочка, сайдбар 236/64 px, bento-дашборд «Главная», превью вкладок при наведении, режим эффектов `glass`/`reduced`; таблицы — на непрозрачной подложке.

**Версия:** `ot-baza@1.4.0`; один менеджер пакетов — **pnpm** (`pnpm-lock.yaml`; `package-lock.json` удалён), правила install-скриптов — в `pnpm-workspace.yaml`.

**Клиенты:** нативный `ОТ-База.exe` (WinForms, ≈258 КБ, `/platform:anycpu`, без web-движка; `build_native_app.ps1`, каталог модулей `native/modules.json`, проверки `--selftest` и `--portable-check`) и WebView2-версия (полный набор функций: PDF, свои `.docx`-шаблоны, ИИ-студия, аудит). Оба работают с одним `data/ot_database.json`.

**Портативность (главный сценарий, 2026-11-27):** папка с EXE копируется на флешку целиком и запускается на любом ПК с Windows 10/11 без установки, прав администратора и интернета. Данные, документы и бэкапы лежат рядом с EXE; абсолютных путей в базе нет. Если рядом писать нельзя — переход в `%LOCALAPPDATA%\OT-Baza` с предупреждением. Один экземпляр на папку (именованный Mutex). Подробности — §4.6 и `README.md`.

**Артефакты (генерируются, в git не входят):** `dist/` (веб-сборка), `dist-offline/` (IIFE), `public/app.html` (офлайн-однофайловик), `ОТ-База.exe` (десктопное приложение: окно WebView2, встроенный `app.html`, данные рядом с программой; собирается `build_desktop_exe.ps1` через `csc.exe`), `ОТ-База (веб).exe` — альтернативный лаунчер с браузером и сервером `127.0.0.1:47821` (`build_web_exe.ps1`), `public/download/*` (нативные бинарники, здесь не собираются — нет MinGW-w64).

**Проверки на момент передачи:** `pnpm test` — **196/196** (21 файл), `pnpm lint` (`tsc --noEmit`, strict) — 0 ошибок, `pnpm build` — успешно, `pnpm audit --prod` — 0 уязвимостей. Браузерные сценарии (предыдущий этап): приём → 8 требований → пакет документов; перевод/увольнение; модули; карточки/таблица; запись файлов в папку; 1440×950 и 1366×768, светлая/тёмная темы, 0 ошибок консоли.

## 4.6. Портативность «флешка → любой ПК» и офлайн-ядро (2026-11-27)

Задача владельца: приложение должно переноситься на флешке и запускаться на любом ПК с Windows, а весь основной функционал (контроль сроков, база нормативки, списки, генерация по шаблонам, импорт/экспорт) работать **без ИИ**. Пароли/шифрование — отложены по решению владельца.

**Что сделано**

1. **Портативный корень данных** — `native/PortablePaths.cs`. Расположение данных определяется один раз: папка EXE проверяется настоящей записью (создание/удаление пробного файла), а не «существует ли папка». Если писать нельзя — переход в `%LOCALAPPDATA%\OT-Baza` + предупреждение при старте и постоянная пометка в статусной строке. Статусная строка теперь показывает «Портативно: <путь>» либо явное предупреждение.
2. **Один экземпляр на папку** — именованный `Mutex` с хешем пути (`Local\OtBaza_<hash>`). Второй запуск из той же папки закрывается сообщением, две разные папки (две флешки) работают независимо.
3. **`--portable-check`** — диагностика без GUI: где данные, можно ли писать рядом с EXE, открывается ли база, сколько таблиц/записей. Код возврата `0` — портативно, `3` — резервная папка; отчёт дублируется в `data/portable-check.txt`.
4. **Надёжная запись базы** — `Store.Save`: `File.Replace` с повтором и резервным копированием (FAT/exFAT-флешки, занятый антивирусом файл), плюс **дневные бэкапы** `data/backups/ot_database_YYYY-MM-DD.json` с ротацией 30 файлов рядом с `ot_database_prev.json`.
5. **Экспорт в Excel** — `native/XlsxWriter.cs` (свой OOXML без библиотек): закреплённая шапка, настоящие даты Excel, числа числами, ведущие нули и «42,5» остаются текстом, текстовая ячейка помечена форматом `@`. Кнопка «Экспорт Excel» в таблицах, выгружается текущая выборка (поиск учитывается).
6. **Даты при импорте** — `native/DateText.cs`: `27.11.2026` из Excel приводится к ISO для полей-дат, иначе сроки по импортированным работникам не считались бы.
7. **Сборка `/platform:anycpu`** вместо `x64`: один и тот же EXE запускается на 32- и 64-битной Windows.
8. **Исправлена потеря BOM** в `build_native_app.ps1` (Windows PowerShell 5.1 читал файл как ANSI и падал на кириллице). Правило: `.ps1` с кириллицей сохранять в UTF-8 **с BOM**.
