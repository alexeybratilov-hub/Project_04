## 1. Дополнительное техническое совещание: Файловая портативность `OT-Baza.exe` (Вариант A)

### 1.1. Совместимость с текущим `launcher.c` и сборочным конвейером
Текущий нативный загрузчик (`/launcher.c`) компилируется кросс-компилятором `x86_64-w64-mingw32-gcc` в 64-битный PE-файл Windows с ресурсами `resources.rc` (`101 RCDATA "public/app.html"`, `102 RCDATA "public/initial_db.json"`).

Проверка окружения подтвердила:
- Установлены `x86_64-w64-mingw32-gcc`, `x86_64-w64-mingw32-windres`, системные библиотеки импорта MinGW-w64: `ws2_32` (`winsock2.h`, `ws2tcpip.h`), `bcrypt` (`bcrypt.h`), `shell32`, `shlwapi`.
- Зависимость от Node.js на машине пользователя **не требуется**: HTTP-сервер полностью встраивается в `launcher.c` на C (Win32 API + WinSock2 + Win32 Cryptography `BCryptGenRandom`).
- Отсутствует локальный Wine/Windows-рантайм в Linux-контейнере: компиляция и структура PE проверяются на месте, а живой запуск на чистой Windows 10/11 и физической USB-флешке подлежит обязательной ручной проверке (отмечено в `HANDOFF.md`).

### 1.2. Схема взаимодействия: EXE ↔ HTTP-сервер ↔ Браузер ↔ Файловое хранилище

```
+-------------------------------------------------------------------------+
|                           OT-Baza.exe (Win64 C)                         |
|                                                                         |
|  1. Инициализация каталога .\ (GetModuleFileNameW -> dirPath)           |
|  2. CreateMutexW("Local\\OTBaza_<FNV1a(dirPath)>") — защита от дублей    |
|     Если экземпляр для этой папки уже запущен -> чтение .\data\.runtime |
|     и открытие уже активного URL в браузере (без второго писателя)       |
|  3. Распаковка .\data\ot_database.json (если нет — из ресурса 102)      |
|     Создание папок: .\data\, .\data\backups\, .\documents\,             |
|     .\normatives\, .\templates\                                         |
|  4. Генерация 128-битного CSPRNG токена (BCryptGenRandom -> hex[32])     |
|  5. bind(127.0.0.1:0) -> getsockname() => эфемерный порт P              |
|  6. Запуск потока HTTP-сервера + запуск браузера:                       |
|     msedge.exe / chrome.exe --app="http://127.0.0.1:<P>/#token=<T>"     |
+------------------------------------+------------------------------------+
                                     |
                      HTTP/1.1 строго 127.0.0.1:<P>
        Заголовки: Host == 127.0.0.1:<P>, Origin == http://127.0.0.1:<P>
                   X-OT-Token: <T> на всех /api/*
                                     |
                                     v
+-------------------------------------------------------------------------+
|                   Браузер (Edge / Chrome App Window)                    |
|                                                                         |
|  - Читает #token=<T> один раз при старте, очищает URL (history.replace) |
|  - ЕДИНСТВЕННЫЙ источник правды: GET /api/database                     |
|  - Запись изменений: PUT /api/database (с If-Match/expectedRevision)    |
|  - Загрузка/скачивание нормативов: /api/files/normatives/<safeName>     |
|  - Сохранение сгенерированных документов/шаблонов в ./documents|templates|
|  - Heartbeat /api/heartbeat каждые 4 с + sendBeacon('/api/shutdown')    |
+------------------------------------+------------------------------------+
                                     |
                     CRITICAL_SECTION (g_fsLock)
                 Проверка размера/JSON + проверка диска USB
                                     |
                                     v
+-------------------------------------------------------------------------+
|                   Корневой каталог приложения (.\)                      |
|                                                                         |
|  .\data\ot_database.json         <- Основная БД + ревизия               |
|  .\data\.ot_database.rev         <- Текущий монотонный счётчик ревизии  |
|  .\data\ot_database.json.tmp     <- Буфер атомарной записи              |
|  .\data\backups\ot_db_prev.json  <- Авто-бэкап перед перезаписью        |
|  .\normatives\<safe_file>        <- Реальные бинарники ГОСТ/СП (.docx)  |
|  .\documents\<safe_file>         <- Сгенерированные приказы/PDF         |
|  .\templates\<safe_file>         <- Пользовательские шаблоны            |
+-------------------------------------------------------------------------+
```

### 1.3. Обязательные требования безопасности и отказоустойчивости
1. **Только loopback (`127.0.0.1`)**: сокет привязывается к `htonl(INADDR_LOOPBACK)` с динамическим свободным портом `0`.
2. **Защита от DNS rebinding**: любой запрос с заголовком `Host`, не совпадающим ровно с `127.0.0.1:<P>` или `localhost:<P>`, отклоняется с HTTP `403 Forbidden`.
3. **Защита от CSRF**:
   - Для всех `/api/*` проверяется `Origin` (если заголовок присутствует, должен совпадать с `http://127.0.0.1:<P>` или `http://localhost:<P>`) И `Sec-Fetch-Site` (если присутствует, не должен быть `cross-site`).
   - Все `/api/*` требуют заголовок `X-OT-Token: <T>` (сравнение в постоянном времени). Исключение — `POST /api/shutdown` через `sendBeacon`, куда передаётся токен в query-параметре или body JSON при совпадении `Origin`.
4. **Безопасность путей и запрет произвольного чтения файлов**:
   - Сервер НЕ раздаёт произвольные файлы с диска: `GET /` отдаёт исключительно встроенный HTML-бандл `app.html` из PE-ресурса `101` (с зашитой мета-конфигурацией порта/режима или через `#token=`), а файловый API работает строго по whitelist каталогов `{normatives, documents, templates}` с жесткой санитизацией имени файла (запрет `/`, `\`, `..`, `:`, управляющих символов, зарезервированных имён Windows `CON/PRN/AUX/NUL/COM1..LPT9`, проверка финального канонического префикса папки).
5. **Атомарная запись, конкурентность и ревизии**:
   - Все дисковые операции защищены `CRITICAL_SECTION`.
   - При старте читается/валидируется `.\data\ot_database.json`; при повреждении JSON пробуется авто-восстановление из `.\data\backups\ot_database_prev.json` или сохраняется копия повреждённого файла `ot_database.corrupted_<ts>.json` с понятной ошибкой пользователю вместо молчаливого сброса.
   - Перед сохранением проверяется `expectedRevision` (`409 Conflict`, если база изменена).
   - Последовательность записи:
     1. Валидация тела JSON (непустой, начинается с `{`, заканчивается `}`, парсится базовая структура `entities`/`tabs`).
     2. Создание резервной копии текущей `ot_database.json` -> `.\data\backups\ot_database_prev.json` (и ротация до 5 снимков `ot_database_bak_N.json`).
     3. Запись во временный файл `.\data\ot_database.json.tmp` с вызовом `FlushFileBuffers`.
     4. Атомарная замена `MoveFileExW(tmp, db, MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)`.
6. **Ошибки ФС и извлечение USB-флешки**:
   - Ошибки Win32 (`ERROR_NOT_READY`, `ERROR_DEV_NOT_EXIST`, `ERROR_BAD_UNIT`, `ERROR_GEN_FAILURE`, `ERROR_DISK_FULL`, `ERROR_ACCESS_DENIED`, `ERROR_WRITE_PROTECT`) маппятся в структурированный JSON HTTP `503`/`507`/`423` с флагом `usbDisconnected: true` и текстом на русском; фронтенд немедленно показывает статус ошибки сохранения с кнопкой повтора и локального скачивания снимка, не скрывая ошибку под «Сохранено».
7. **Корректное завершение сервера**:
   - Основной поток слушает сокеты до наступления условия завершения: явный `POST /api/shutdown` (если все вкладки/окна закрыты и не пришёл новый ping в течение 3 с) либо отсутствие `/api/heartbeat` в течение grace-таймаута (например, 45 с после потери последнего клиента; при активном UI клиент шлёт heartbeat раз в 4 с). По завершении закрывается `listenSocket`, очищается `WSACleanup()`, удаляется `.\data\.ot_runtime.json` и освобождается именованный `Mutex`.

### 1.4. План безопасной миграции данных (`localStorage` -> `./data/ot_database.json`)
Чтобы исключить «двойную правду» (split-brain):
- При запуске из-под нативного `OT-Baza.exe` (режим `native-fs`, определяется через наличие токена + `/api/health` на loopback-сервере):
  1. Основным источником правды объявляется `./data/ot_database.json`.
  2. Если при первой загрузке в `localStorage['ot_base_database_v1']` обнаружены пользовательские данные, а файл на диске содержит исходное демо-состояние (или пользователь подтверждает слияние при наличии расхождения), приложение предлагает/выполняет однократный перенос в `./data/ot_database.json` через `PUT /api/database`, сохраняет архивную метку миграции и **очищает ключ `ot_base_database_v1` в `localStorage`**, чтобы больше никогда не возникало расхождения.
- При работе в веб-предпросмотре / браузере вне `OT-Baza.exe` (режим `web-preview`):
  - Работает `localStorage` с явным отображением режима «Браузерный режим (локальное хранилище браузера)» и корректным перехватом `QuotaExceededError`.

## 2. Связанные столбцы в `DataGrid` (Согласованный компромисс)

- В связанных ячейках (`type === 'relation'`) остаётся прямой выпадающий выбор допустимых значений из мастер-таблицы (никакого произвольного ручного ввода текста в самой ячейке).
- Удалена блокирующая иконка `<Lock />` рядом с обычной ячейкой: для перехода к строке-источнику в мастер-вкладке добавляется отдельная аккуратная кнопка перехода со стрелкой (`ExternalLink` / `ArrowUpRight`) и пункт в меню/подсказке; сам клик по значению открывает нативный/управляемый выбор из мастера (сохраняя `onDoubleClick` на строку или переход по кнопке).
- Прозрачный `<select className="opacity-0">`, перехватывавший всю ячейку и ломавший клики/двойной клик/доступность, заменяется явным управляемым селектором с видимой границей фокуса, проверкой активного юрлица и списка допустимых значений.
- **Каскадные обновления и защита от тихого сброса**:
  - Если изменение одного связанного поля (например, «Должность») делает другое уже заполненное связанное поле (например, «Подразделение») несовместимым с текущими записями Мастера — система **не очищает зависимые поля молча**: если есть ровно 1 допустимое значение в Мастере, предлагает/подставляет его с уведомлением; если допустимых значений несколько или 0, запрашивает явное действие пользователя или помечает несоответствие с возможностью отката.
  - Переименование или удаление мастер-строки / мастер-колонки / мастер-вкладки проходит через `integrityService`: отображается точное число затронутых дочерних записей и таблиц до подтверждения, без обрыва ссылок в «ничто».

## 3. Шрифт с кириллицей для `jsPDF` и тестовый раннер `Vitest`

1. **PDF-шрифт**: Выбран системный локально доступный шрифт **`DejaVuSans.ttf`** + **`DejaVuSans-Bold.ttf`** (пакет `fonts-dejavu-core` на машине сборки).
   - Проверка лицензии (`/usr/share/doc/fonts-dejavu-core/copyright`): лицензия **Bitstream Vera + Public Domain для изменений DejaVu** — полностью пермиссивная, разрешает встраивание и распространение в составе ПО при сохранении уведомления о правах Bitstream. (Альтернатива Liberation v1 имела GPLv2 + font exception, поэтому `DejaVuSans` юридически чище.)
   - Шрифт конвертируется в локальный TypeScript-модуль `src/data/cyrillicFont.ts` в base64 и регистрируется через `doc.addFileToVFS` / `doc.addFont` без сетевых запросов.
2. **Автотесты (`vitest`)**: Устанавливается строго в `devDependencies` (`"test": "vitest run"`), не попадает ни в клиентский бандл `dist/`, ни в `app.html`.

### Ключевые риски и меры снижения
| Риск | Мера снижения |
|------|----------------|
| Невозможность запустить Win32 PE (`.exe`) в headless Linux без Wine | Жёсткая компиляция с `-Wall -Wextra -Werror` на `x86_64-w64-mingw32-gcc`, проверка логики протокола и парсинга запросов, чёткая фиксация требуемых ручных тестов на Windows 10/11 и USB в `HANDOFF.md` |
| Блокировка загрузки/сохранения или конфликт при нескольких окнах на одной флешке | Именованный `Mutex` на путь каталога + монотонный `revision` + `CRITICAL_SECTION` + HTTP `409 Conflict` |
| Рост размера `app.html` из-за шрифта `DejaVuSans` | Встраивание Regular + Bold ~1.4 МБ (~0.7 МБ после gzip/zip); проверка размера итогового `OT-Baza.exe` и загрузки UI |
| Ложные каскадные изменения при совпадении имён должностей/подразделений | Предварительный аудит через `integrityService`, поддержка контекста юрлица и явное уведомление/подтверждение |

### Критерии приёмки P0
1. `OT-Baza.exe` компилируется MinGW-w64 без ошибок и предупреждений со встроенным HTTP-сервером на `127.0.0.1`, токеном сессии, проверками `Host`/`Origin`, атомарной записью `ot_database.json`, резервным копированием и обработкой ошибок ФС/USB.
2. При работе в режиме `native-fs` UI читает и пишет базу только в `./data/ot_database.json`; одноразовая миграция из `localStorage` не оставляет двойного источника правды; ошибки сохранения отображаются в интерфейсе явно.
3. Прикрепляемые нормативные акты (`.docx`, `.pdf`, `.txt`) сохраняют реальное содержимое (в `./normatives/` или `dataBase64`), доступны для скачивания и не теряются при смене юрлица.
4. Все модальные окна синхронизируют состояние с активным юрлицом/вкладкой/строкой при открытии и переключении.
5. Удаление строк, столбцов и вкладок-мастеров проверяет зависимости, предупреждает пользователя о числе затронутых ссылок и очищает разорванные привязки без «висячих» `relation` и тегов.
6. Сборка проекта (`npm run build`, `npm run lint`), автотесты (`npm test`) и сборка Windows-пакета (`python3 build_native_windows.py`) проходят без ошибок.

1. **Отказ от «генератора шаблонов» в пользу привязки «Шаблоны» к таблицам и разделам (`src/components/TemplatesModal.tsx`, `src/types/database.ts`, `src/data/builtInTemplates.ts`)**:
   - Модальное окно `TemplateGeneratorModal` заменено на `TemplatesModal`. В верхнем меню `«Документы -> Шаблоны»` открывается общий каталог шаблонов, сгруппированный по разделам (`DOCUMENT_CATEGORIES`), с указанием привязанной таблицы и отдельным разделом архивных шаблонов.
   - В панели инструментов каждой вкладки (`DataGrid.tsx`) кнопка `«Шаблоны»` открывает набор шаблонов, привязанных конкретно к активной таблице (`tpl.tabId === currentTab.id && !tpl.isArchived`). Пользователь может создавать, редактировать, удалять шаблоны и формировать DOCX/PDF из предпросмотра.
2. **Удаление таблицы с выбором «Удалить всё или переместить в архив» (`src/services/integrityService.ts`, `src/App.tsx`)**:
   - `integrityService.getTabDeleteImpact` учитывает не только разрыв связей с мастером и очистку тегов, но и привязанные шаблоны (`affectedTemplatesCount`, `affectedTemplateNames`) и сформированные документы (`affectedDocsCount`).
   - При удалении таблицы диалог предупреждает о потере связей и шаблонов и предлагает выбор: **«Да — переместить в архив»** (шаблоны получают `isArchived: true`, `archivedFromTabName`, активные файлы из этой таблицы переносятся в `<Категория>/АРХИВ/<дд.мм.гггг>/`) либо **«Нет — удалить всё»** (безвозвратное удаление привязанных шаблонов и документов).
3. **Прямая позиционная вставка из Excel (без кнопки «Вставить массивом») (`src/services/excelService.ts`, `src/components/DataGrid.tsx`)**:
   - Кнопка `«Вставить массивом»` и отдельная модалка удалены. Копирование 1 или нескольких столбцов (любого числа `<=` количеству столбцов во вкладке) и вставка по `Ctrl+V` работают прямо при клике по ячейке или пустому слоту таблицы; ошибка выдаётся только при превышении числа столбцов таблицы.
   - Обязательно наличие хотя бы одного столбца с наименованием; позиционная вставка ниже кликнутой строки (`splice(insertIndex, 0, ...)`) сдвигает нижележащие строки вниз; многоколоночная вставка и связанные столбцы с мастер-таблицами по-прежнему проверяются транзакционно через `validateLinkedColumns`.
