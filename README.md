# ОТ-База

Автономное приложение для специалиста по охране труда: таблицы со связями «мастер → зависимые», импорт/экспорт Excel, генерация документов Word/PDF по тегам, реестр нормативных актов, контроль сроков и локальная ИИ-студия (Ollama / OpenAI-совместимые API).

Работает в двух режимах:

| Режим | Как запускается | Где хранятся данные |
|---|---|---|
| **file-handle** (рекомендуется для веба) | `dist/` или `pnpm dev` в Chrome/Edge, затем «Файл → Рабочая папка на диске…» | `data/ot_database.json` в выбранной папке + бэкапы в `data/backups/` (File System Access API) |
| **native-fs** | `OT-Baza.exe` (Windows 10/11 x64) — поднимает локальный HTTP-сервер на `127.0.0.1` и открывает отдельное окно браузера | `./data/ot_database.json` рядом с программой, атомарная запись + бэкапы в `./data/backups/` |
| **web / preview** | `pnpm dev` или собранный `dist/` в любом браузере | `localStorage` браузера (одна копия на домен) |

`file-handle` — это веб-версия без нативного сервера: браузер получает доступ к одной выбранной папке и пишет файл базы сам. Работает в Chrome и Edge на `https://` или `http://localhost` (нужен secure context); в Firefox/Safari остаётся только хранение в браузере. Первый запуск требует системного диалога выбора папки, после перезагрузки браузер может попросить подтвердить доступ — это его политика безопасности.

Первый режим даёт файловое хранение на диске/флешке, второй — работу без установки и без `.exe`.

## Быстрый старт (веб-версия)

```bash
pnpm install
pnpm dev          # http://localhost:3000
```

Production-сборка и локальный предпросмотр:

```bash
pnpm build
pnpm preview      # http://localhost:4173
```

Собранный `dist/` — статический сайт: его можно разложить на любой хостинг (Nginx, GitHub Pages, внутренний сервер). Все данные при этом живут в `localStorage` браузера пользователя, серверная часть не нужна.

## Сборка артефактов для Windows

```bash
# только веб-артефакты: dist-offline/ + public/app.html + dist/
python build_native_windows.py --skip-native

# полный релиз: дополнительно OT-Baza.exe и OT-Baza-Windows.zip
python build_native_windows.py
```

Полная сборка требует Node.js в `PATH` (или переменной `NODE_BIN`) и MinGW-w64 (`x86_64-w64-mingw32-gcc`, `x86_64-w64-mingw32-windres`). Бинарники `OT-Baza.exe` / `OT-Baza-Windows.zip` **не хранятся в git** (`public/download/` в `.gitignore`) — они собираются локально и публикуются как релизные артефакты. Если их нет, интерфейс честно отключает кнопки скачивания.

`public/app.html` — одностраничный офлайн-вариант (весь код, стили и шрифты внутри одного файла). Открывается двойным щелчком из `file://`.

## Структура

```
src/
  App.tsx                 — оболочка: состояние БД, вкладки, сохранение, модалки
  components/             — UI (DataGrid, модалки, MenuBar/TabBar/StatusBar, ui/*)
  services/               — storageService, integrityService, excelService,
                            documentGenerator, deadlineService, localApiClient…
  data/                   — встроенные шаблоны, нормативные акты, шрифт для PDF
  types/database.ts       — модель данных (DatabaseState, LegalEntity, Tab, Column…)
launcher.c                — нативный Windows-лаунчер и локальный HTTP-сервер

docs/                     — исследовательские артефакты (прототипы)
```

## Интерфейс

Визуальный язык — **Liquid Glass + Bento**: полупрозрачная «хромовая» оболочка (шапка, меню, вкладки, статус-бар) поверх мягкого градиентного canvas, данные при этом остаются на непрозрачной высококонтрастной поверхности.

- Стартовый экран — **«Главная»** (`src/components/DashboardView.tsx`): bento-сетка из стеклянных карточек с KPI (просрочено / скоро / записей / документов), лентой ближайших сроков, списком организаций, быстрыми действиями, недавними документами и обзором таблиц.
- Стеклянные токены и утилиты — в `src/index.css` (`.lg-chrome`, `.lg-card`, `.lg-data-surface`); при `prefers-reduced-transparency` и `prefers-reduced-motion` эффекты отключаются автоматически.
- Все действия выполняются реальными обработчиками (переход к табу, смена организации, открытие модалок), без декоративных заглушек.

## Модули и обязательства (ядро приложения)

Приложение построено как конструктор этапов: **модуль = этап или точка контроля = отдельная вкладка** со своими шаблонами и сроками.

- Базовая конфигурация новой базы — два модуля: **«Штатное расписание»** и **«Сотрудники»** (мастер-реестр).
- Остальные этапы включаются в «Вкладки → Модули этапов»: инструктажи, медосмотры, СИЗ, СОУТ, несчастные случаи. Отключение модуля **скрывает вкладку, но не удаляет данные**.
- Матрица требований (`src/data/modules.ts`) не зависит от включённых модулей: при приёме на работу создаётся полный пакет обязательств — вводный инструктаж (день приёма), первичный инструктаж и проверка знаний (до месяца), направление на медосмотр и карточка СИЗ (до начала работы), повторный инструктаж (6 мес.), периодический медосмотр (12 мес.). У каждого требования указана нормативная база.
- Карточка работника: чек-лист «что должно быть и когда», кнопка **«Сформировать пакет»** (Word-документы по шаблонам), отметка **«Выполнено»** — для периодических требований сразу создаётся следующая задача.
- Контрольные точки: если документ не оформлен к наступлению срока, работник попадает в блок «Пакеты документов» на «Главной» и в список «требует внимания».
- **События жизненного цикла**: приём, перевод, увольнение, несчастный случай. Событие регистрируется в карточке работника и сразу порождает свой набор требований (например, перевод — приказ, внеплановый инструктаж, проверка знаний; увольнение — приказ, возврат СИЗ, закрытие карточки; несчастный случай — акт, расследование, внеплановый инструктаж). Повторные события не дублируют требования внутри одного события, но создают новый пакет.
- **Матрица зависит от должности и условий труда**: руководителям добавляется обучение по охране труда (раз в 3 года), периодичность медосмотра берётся из класса условий труда (2.0 — 24 мес., 3.x — 12 мес.). Класс определяется по должности из штатного расписания.
- **Документы сохраняются в рабочую папку**: при подключённой папке (File System Access) каждый сформированный документ пишется в `documents/<Категория>/<файл>.docx` рядом с базой, помимо скачивания браузером.
- Уволенные сотрудники помечаются в списке и исключаются из расчёта «без пакета».
- Сроки считаются от даты события; при изменении даты приёма незакрытые сроки пересчитываются, выполненные — нет.

Код: `src/data/modules.ts` (реестр модулей, события, правила и условия), `src/services/moduleService.ts` (установка/снятие), `src/services/obligationService.ts` (расчёт сроков, пакеты, события, контрольные точки), `src/components/EmployeesView.tsx` и `EmployeeCardModal.tsx`.

## Ограничения

- `file-handle` работает только в Chromium-браузерах (Chrome/Edge) и только на `https://` или `localhost`. Запись не атомарна: перед перезаписью текущая база копируется в `data/backups/ot_database_prev.json`.
- Нативный `.exe` проверяется только на Windows 10/11 x64; сборка и запуск требуют MinGW-w64.
- В режиме `web-preview` крупные вложения (>1.5 МБ) не кэшируются в `localStorage` — для файлов на диске используйте `file-handle` или `OT-Baza.exe`.
- Импорт данных из Excel не приводит значения «насильно»: нечисло в числовом столбце или текст в дате отклоняется с отчётом о расхождениях.
