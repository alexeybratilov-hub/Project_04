## 1. Назначение

«ОТ-База» — рабочее место специалиста по охране труда. Приложение снимает с него бумажную работу: само знает, какие документы и сроки положены работнику, формирует документы по шаблонам и контролирует исполнение.

Ключевая идея: **событие → пакет обязательств (документы + сроки) → контроль**. Специалист не помнит, что нужно сделать, — он видит готовый чек-лист по каждому человеку.

---

## 2. Что происходит при приёме на работу

1. Сотрудник добавляется в модуль «Сотрудники» (дата приёма подставляется автоматически).
2. Приложение создаёт **8 обязательств**:

| Требование | Срок | Основание |
|---|---|---|
| Приказ о приёме на работу | день приёма | ТК РФ, ст. 68 |
| Вводный инструктаж по охране труда | день приёма | ПП 2464, п. 10 |
| Первичный инструктаж на рабочем месте | +30 дней | ПП 2464, п. 13 |
| Проверка знаний требований ОТ | +30 дней, далее ежегодно | ПП 2464, п. 32 |
| Направление на предварительный медосмотр | до начала работы, далее 12–24 мес. | Приказ 29н |
| Карточка учёта выдачи СИЗ | до начала работы | Приказ Минтруда 766н |
| Повторный инструктаж | +180 дней, далее каждые 6 мес. | ПП 2464, п. 16 |
| Периодический медосмотр | +365 дней | Приказ 29н |

3. Дополнительно для руководящих должностей: обучение по охране труда — 60 дней, далее раз в 3 года (ПП 2464, п. 46).
4. Кнопка **«Сформировать пакет»** создаёт документы Word по шаблонам и складывает их в реестр и в рабочую папку.
5. Кнопка **«Выполнено»** закрывает требование; для периодического сразу создаётся следующая задача с новой датой.
6. Если документ не оформлен к сроку — работник попадает в блок «Пакеты документов» на «Главной» и в список «требует внимания».

## 3. События жизненного цикла

| Событие | Что создаётся автоматически |
|---|---|
| **Приём** | 8 требований (см. выше) |
| **Перевод** | приказ о переводе, внеплановый инструктаж (день перевода), проверка знаний (+30 дней) |
| **Увольнение** | приказ о прекращении договора, возврат СИЗ, закрытие личной карточки |
| **Несчастный случай** | акт (+1 день), расследование (+3 дня), внеплановый инструктаж (+7 дней) |

Повторное событие создаёт новый пакет; повторная регистрация того же события не дублирует требования. Уволенные сотрудники помечаются в списке и исключаются из расчёта пакетов.

## 4. Модульная архитектура

Модуль = этап или точка контроля = отдельная вкладка со своими шаблонами и сроками.

| Модуль | Вкладка | Что даёт |
|---|---|---|
| Штатное расписание (базовый) | `tab_positions` | должности, подразделения, класс условий труда |
| Сотрудники (базовый) | `tab_employees` | мастер-реестр, источник обязательств |
| Инструктажи | `tab_instructions` | инструктажи, проверка знаний |
| Медосмотры | `tab_med` | направления, даты, заключения |
| Выдача СИЗ | `tab_siz` | карточки, нормы, срок носки |
| СОУТ | `tab_factors` | вредные факторы, классы, Приказ 29н |
| Несчастные случаи | `tab_incidents` | регистрация и расследование |

- Новая база стартует с **двух базовых** модулей; остальные включаются в «Вкладки → Модули этапов».
- Отключение модуля **скрывает вкладку, данные остаются**; включение возвращает всё на место.
- Старые базы при обновлении ничего не теряют: набор модулей выводится из фактически существующих вкладок.

## 5. Матрица требований

Правила лежат в `src/data/modules.ts` и учитывают:

- **должность** — подстроки названия (например, «начальник», «мастер» → обучение по ОТ раз в 3 года);
- **класс условий труда** — берётся из штатного расписания: 2.0 → медосмотр раз в 24 мес., 3.1–3.4 → раз в 12 мес.;
- **периодичность** — после выполнения создаётся следующая задача;
- **нормативную базу** — у каждого требования указан документ-основание.

Расширение матрицы — это данные, а не переписывание кода.

## 6. Документы, импорт и готовность к проверке ГИТ

- **10 встроенных шаблонов**: 8 индивидуальных (приказ ответственного за ОТ, о приёме, переводе, увольнении, направление на МО, карточка СИЗ, протокол проверки знаний, акт о НС) и 2 групповых (сводный протокол проверки знаний и лист ознакомления с ЛНА/ИОТ с разметкой `[ТАБЛИЦА]...[/ТАБЛИЦА]`).
- Подстановка тегов: реквизиты организации, ФИО, табельный номер, должность, подразделение, дата приёма, дата события, СНИЛС, факторы 29н, нормы СИЗ 766н.
- Поддержка собственных `.docx`-шаблонов (OOXML, включая таблицы и колонтитулы) и выгрузка пакетов документов единым **`.zip`-архивом**.
- Реестр сгенерированных документов с категориями и АРХИВом версий.
- При подключённой рабочей папке документы дополнительно пишутся в `documents/<Категория>/<файл>.docx`.
- PDF-генерация доступна для текстовых шаблонов и групповых протоколов (кириллический шрифт DejaVuSans встроен).
- **Справочник норм (`occupationNorms.ts`)**: привязка должностей к вредным факторам Приказа № 29н и нормам СИЗ Приказа № 766н с автопересчётом обязательств.
- **Пресет 1С:ЗУП**: быстрый импорт кадровых выгрузок из Excel с автосозданием отсутствующих должностей в штатном расписании.
- **Готовность к проверке ГИТ и календарь РФ**: на «Главной» отображается индекс готовности по 9 категориям (с перечнем пробелов и выгрузкой в DOCX/PDF/XLSX); в «Контроле сроков» предзагружаются праздники РФ на 2026 и 2027 гг.

## 7. Хранение данных

| Режим | Как работает | Где данные |
|---|---|---|
| **Рабочая папка** (веб, Chrome/Edge) | «Файл → Рабочая папка на диске…», доступ через File System Access API | `data/ot_database.json`, бэкап `data/backups/ot_database_prev.json`, документы в `documents/` |
| **Веб-браузер** | обычное открытие сайта | `localStorage` браузера |
| **OT-Baza.exe** | нативный сервер `127.0.0.1`, отдельное окно | `./data/ot_database.json` рядом с программой |

Сохранность: бэкап перед перезаписью, восстановление из архива, защита от потери при ошибках записи, баннер ошибки сохранения, ErrorBoundary с выгрузкой JSON-копии.

## 8. Интерфейс

- **Liquid Glass + Bento**: стеклянная оболочка (шапка, меню, вкладки, статус-бар, сайдбар) поверх градиентного canvas; данные — на непрозрачной поверхности.
- **Главная** — bento-дашборд: KPI, лента сроков, организации, пакеты документов, быстрые действия, недавние документы, обзор таблиц.
- **Гибридная навигация**: сайдбар 236 px / 64 px (сворачивается, состояние запоминается), разделы «Обзор» и «Этапы».
- **Превью вкладок** при наведении: реальные данные, задержки 280/180 мс, закрытие по Esc.
- **Режим эффектов**: «Стекло / Облегчённый» + системные `prefers-reduced-*`.
- Таблицы и «Контроль сроков» остаются на плотной высококонтрастной подложке.

## 11. Безопасность и сохранность

- **Отказ от уязвимой библиотеки `xlsx@0.18.5`**: импорт и экспорт `.xlsx`/`.xlsm`/`.csv` переведены на собственный `ooxmlWorkbookService.ts` на базе `fflate`; 0 high/critical уязвимостей в runtime-зависимостях.
- **152-ФЗ (обезличивание для LLM)**: при обращении к облачным API персональные данные заменяются локальными маркерами и восстанавливаются после ответа без передачи ПДн вовне.
- **Шифрованные резервные копии и защита от prototype pollution**: в `BackupModal` доступно шифрование резервных копий алгоритмом `PBKDF2-SHA256` (210 000 итераций) + `AES-256-GCM`; парсер резервных копий блокирует ключи `__proto__`, `constructor`, `prototype`.
- **Журнал аудита (`AuditLogModal`)**: фиксация изменений записей (было → стало), импорта, событий работников, изменения структуры столбцов и восстановления из копии с экспортом журнала в Excel.
- **Authenticode (Windows)**: в `WindowsPortableModal` и «Справке» добавлена инструкция по корпоративной подписи EXE через `signtool.exe`.
- Импорт Excel и вставка не подменяют данные: нечисло в числовом столбце и текст в дате отклоняются с отчётом; даты не сдвигаются на день.
- Миграция `localStorage → диск` очищает копию только после подтверждённой записи; очередь записи сериализована.
- Нативный слой: запуск браузера по абсолютному пути, ожидание клиентских потоков при выходе, `SO_EXCLUSIVEADDRUSE`, зануление сессионного токена.
- Внешних CDN нет: шрифты и библиотеки локальные, приложение работает офлайн.

## 12. Как запустить

```bash
# веб-версия для разработки
pnpm install
pnpm dev            # http://localhost:3000

# production-сборка и предпросмотр
pnpm build
pnpm preview        # http://localhost:4173

# проверки
pnpm check          # lint + test + build

# артефакты (app.html + dist)
python build_native_windows.py --skip-native

# полный Windows-релиз (нужен MinGW-w64)
python build_native_windows.py
```

Для работы с файлами на диске: открыть приложение в Chrome/Edge на `http://localhost` или `https://`, затем «Файл → Рабочая папка на диске…».

## 14. Ограничения и что дальше

**Ограничения**

1. `OT-Baza.exe` и ZIP собираются только на Windows с MinGW-w64 — в текущей среде компилятора нет; живые проверки нативного рантайма не проводились.
2. Матрица требований покрывает типовые случаи (приём, перевод, увольнение, несчастный случай). Полный справочник по Приказу 29н и ПП 2464 (по должностям и факторам) — следующий шаг, это данные, а не код.
3. Пакет документов формируется в DOCX; PDF доступен отдельно для текстовых шаблонов.
4. Рабочая папка поддерживается в Chrome и Edge; Firefox и Safari остаются на `localStorage`.
5. Приложение однопользовательское, без серверной синхронизации.
