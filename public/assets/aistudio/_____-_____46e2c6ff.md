# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Приложение для ведения базы данных по охране труда (рабочее название: «ОТ-База»)

**Версия ТЗ:** 1.1 (добавлены: portable-исполнение, нормативные документы, локальная LLM)
**Дата:** 2026-11-09

---

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Тип приложения | Десктоп, офлайн |
| ОС | Windows 10/11 (64-bit) |
| Пользователей | 1 (один пользователь на одном ПК) |
| Подключение к интернету | Не требуется |
| Бюджет | 0 ₽ — только бесплатные технологии, разработка и эксплуатация локально |
| Масштаб данных | до 20 вкладок, до 5000 строк на вкладку |
| Персональные данные | Присутствуют → хранение строго локально, файл базы не покидает ПК |
| Формат поставки | **Portable-версия (обязательно)**: приложение запускается с любого носителя (USB-флешка, внешний диск) на любой машине с Windows 10/11 без установки. База, шаблоны и нормативные документы хранятся рядом с приложением или в выбранной папке на носителе |

**Назначение:** приложение для специалиста по охране труда: ведение структурированных таблиц (контингент работников, штатное расписание, вредности по СОУТ/для МО и т.д.), связь таблиц между собой через «основные» (мастер-)вкладки, генерация документов из Word-шаблонов по тегам.

---

## 2. Основной функционал

### 2.1. Вкладки (таблицы)
- Панель вкладок, создание произвольного количества вкладок (лимит 20) с пользовательскими названиями.
- В каждой вкладке: добавление, переименование, удаление, изменение порядка столбцов; добавление/удаление строк.
- Типы столбцов: текст, число, дата, выпадающий список, да/нет, файл/ссылка.
- Удаление столбца или всей вкладки — только с подтверждением и предупреждением о зависимых связях.

### 2.2. Импорт из Excel
- Загрузка .xlsx / .xlsm / .csv.
- Режим «как есть»: вкладка создаётся автоматически по структуре файла (названия столбцов из первой строки, тип данных определяется по содержимому).
- Режим «в существующую вкладку»: сопоставление столбцов файла со столбцами вкладки, просмотр перед импортом.
- Импорт транзакционный: при ошибке — откат, ничего не остаётся в «полураспакованном» виде.
- **На каждой вкладке — постоянная краткая подсказка** о том, как должен выглядеть файл для корректного импорта (формат дат, разделители, кодировка CSV — UTF-8 и т.п.). Подсказку можно сворачивать.

### 2.3. Связи между вкладками (мастер → зависимые)

Пример сценария: вкладка «Штатное расписание» (мастер) содержит столбец «Наименование должности». В новой вкладке «Список работников» создаётся столбец с тем же именем → система предлагает связать его со столбцом мастера.

- **Распознавание связи:** при создании столбца с именем, совпадающим со столбцом существующей вкладки, пользователю предлагается назначить ту вкладку основной.
- **Выбор значений в зависимой вкладке:**
  - По одному: в каждой строке связанного столбца — выпадающий список со значениями из соответствующего столбца мастера.
  - Массивом: вставка столбца из Excel-таблицы. Все значения проверяются на совпадение со списком мастера. При полном совпадении — вставка; при расхождениях — импорт отменяется, программа выводит список несовпавших значений и номера строк.
- **Блокировка правок:** данные связанных столбцов в зависимой вкладке — только чтение.
  - При попытке редактирования — сообщение: «Эти данные вносятся в основной вкладке "Штатное расписание". Перейти туда для внесения правок?» Кнопки «Да» / «Нет».
  - По «Да» — переход в основную вкладку с позиционированием на нужную ячейку.
  - При упорных повторных попытках — усиленное предупреждение (без блокировки самого пользователя).
- **Синхронизация:** изменение значения в мастере автоматически обновляет его во всех зависимых вкладках. Переименование/удаление значения в мастере — с предупреждением о влиянии на N строк в зависимых вкладках.
- **Индикация:** связанные столбцы помечаются значком (замок/цепочка), экран «Схема связей» показывает диаграмму мастер → зависимые.

### 2.4. Пул тегов (общий)
- Единый справочник тегов для всех вкладок и шаблонов. Формат: `{Имя_тега}`.
- Тег привязывается к столбцу конкретной вкладки; при генерации документа берётся значение из выбранной строки.
- Вкладка «Теги»: список всех тегов, их привязки, добавление/переименование/удаление.
- Валидация: предупреждение о «осиротевших» тегах (есть в шаблонах, но не привязаны к данным).

### 2.5. Шаблоны и генерация документов
- Шаблоны — обычные .docx файлы, готовятся **вне приложения** (в Word), загружаются через поле загрузки.
- В поле загрузки шаблона: кнопка «Открыть вкладку Теги» (теги не выводятся в самом поле — чтобы не было проматывания).
- Привязка шаблона к конкретной вкладке (одна вкладка → несколько шаблонов).
- Генерация: по одной строке или пакетно (по всем/выбранным строкам).
- Замена плейсхолдеров `{тег}` на значения; таблицы в шаблоне заполняются массивами (например, список работников цеха — повторяющаяся строка таблицы).
- Именование результатов по шаблону имени файла: `{ФИО}_инструктаж_2026.docx`.
- Форматы результата: **docx и PDF** (оба обязательны).
- Сгенерированные документы сохраняются в выбранную пользователем папку.

### 2.6. Нормативные документы (приложения к вкладкам)
- К каждой вкладке можно прикрепить произвольное количество файлов: .docx, .txt, .pdf и др. (нормативные требования, СП, ГОСТ, приказы, положения).
- Файлы хранятся внутри папки приложения/базы (копируются при прикреплении, а не только ссылка).
- Просмотр файлов прямо из приложения (встроенный просмотрщик или открытие в системной программе по умолчанию).
- Список прикреплённых файлов отображается на вкладке, файлы можно удалять/заменять.

### 2.7. Генерация документов через локальную LLM
- Приложение подключается к локально запущенной LLM через localhost API (совместимость прежде всего с **Ollama**, при возможности — с llama.cpp / OpenAI-совместимыми локальными серверами).
- Настройки подключения вынесены в интерфейс: адрес (по умолчанию http://localhost:11434), название модели, тайм-аут, проверка связи («Проверить подключение»).
- Работа без интернета: LLM крутится на той же машине; при недоступности LLM приложение полностью работоспособно в режимах «таблицы + теговая подстановка» (раздел 2.5), LLM-функции отключаются с понятным сообщением.
- Сценарий генерации: пользователь выбирает вкладку, строку (или строки), шаблон документа (приказ, инструкция, положение и т.д.) → приложение формирует запрос, включающий:
  1. данные из выбранной строки (по привязанным тегам);
  2. текст прикреплённых к вкладке нормативных документов (раздел 2.6);
  3. структуру/требования самого шаблона.
- Результат генерации показывается пользователю для проверки и редактирования **до сохранения**; сохранение — в .docx и/или .pdf в выбранную папку.
- Ведётся журнал генераций (дата, шаблон, модель, исходный запрос/краткое содержание) — для контроля качества и повторяемости.

### 2.8. Экспорт и обслуживание
- Экспорт любой вкладки в .xlsx.
- Поиск и фильтрация по всем вкладкам.
- Резервное копирование всей базы в один файл; восстановление из копии.
- При первом запуске — выбор папки хранения базы; повторные запуски открывают её автоматически.

## 3. Требования к реализации

- **Стек (рекомендация, подлежит согласованию):** Python + PySide6 (Qt) + SQLite. Бесплатные лицензии, полностью офлайн, SQLite надёжно держит объёмы до 5000×20.
- **Альтернатива:** Tauri + SQLite (если интерфейс важнее скорости разработки) — обсудить с разработчиком.
- Данные, шаблоны и нормативные документы хранятся в выбранной пользователем папке (на любом носителе); база — в открытом формате (SQLite) + возможность выгрузки всего в Excel.
- **Portable-исполнение обязательно:** никакой установки в систему, записи в реестр и зависимости от конкретного ПК. Папку с приложением можно переносить между машинами с Windows 10/11 (включая работу с USB-носителя); пути к данным — относительные или автопоиск папки базы рядом с приложением.
- **Дизайн интерфейса:** сначала визуализируются макеты (wireframes) ключевых экранов: список вкладок, таблица с выпадающим списком связанного столбца, диалог предупреждения о переходе, экран тегов, загрузка шаблона, схема связей. Макеты утверждаются заказчиком, только после этого — разработка UI.

## 4. Критерии приёмки (ключевые)

1. Создание вкладки, столбцов, строк; импорт xlsx «как есть» создаёт вкладку по структуре файла.
2. Связанный столбец в зависимой вкладке: выпадающий список из мастера; вставка массивом с отчётом о расхождениях.
3. Правка связанной ячейки блокируется; диалог «Перейти в основную вкладку? Да/Нет»; по «Да» — переход к нужной ячейке.
4. Изменение в мастере мгновенно отражается во всех зависимых вкладках.
5. Загрузка docx-шаблона, привязка тегов, генерация docx и PDF по одной строке и пакетно.
6. На каждой вкладке видна сворачиваемая подсказка по формату файла импорта.
7. Работа полностью офлайн; база хранится локально; есть резервное копирование/восстановление.
8. До разработки UI утверждены макеты всех ключевых экранов (добавить: список прикреплённых нормативных файлов, настройки подключения LLM, экран проверки результата генерации).
9. Приложение запускается с USB-носителя на «чистой» машине с Windows 10/11 без установки и без интернета.
10. К вкладке можно прикрепить .docx/.txt/.pdf, файл копируется в хранилище базы, открывается из приложения.
11. При запущенной Ollama приложение генерирует документ (приказ/инструкцию/положение) по шаблону с учётом данных строки и прикреплённых нормативных документов; результат редактируется перед сохранением; при выключенной LLM приложение работает без ограничений базового функционала.

## 5. Открытые вопросы (для обсуждения с разработчиком)

1. Portable-версия vs инсталлятор.
2. Точный формат подсказок по импорту — составить список типичных файлов заказчика.
3. Нужен ли журнал изменений (audit log) в первой версии — можно отложить.
4. Повторяющийся импорт из одного файла (обновление данных) — в v1.0 или v1.1?
5. LLM: какая модель/размер ожидается (зависит от ОЗУ и видеокарты машин, где будет запускаться)? Минимальные требования к железу для LLM-режима.
6. Лимит объёма нормативных документов, передаваемых в запрос LLM (контекстное окно модели): нужна ли стратегия разбиения больших документов на части?
7. Нужен ли в первой версии выбор «температуры»/параметров генерации или достаточно значений по умолчанию?
